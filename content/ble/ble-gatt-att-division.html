在上一篇中，我们把 BLE 的数据存储拆解成了一张“Excel 属性大表”：最底层是每一行 Attribute，往上组合成 Characteristic，再组合成 Service。这个模型解决了“数据在设备里怎么存、怎么按业务划分”的问题。

一句话点破本质：

GATT 管的是“业务规约与表格设计”，负责让数据有意义；

ATT 管的是“空口发包与搬运”，负责把这行单元格里的裸字节准确发出去。

一、 概念联动：GATT 与 ATT 的职责切分

对比维度

GATT（Generic Attribute Profile）

ATT（Attribute Protocol）

 

在上一篇中的定位

“表格设计规范”：规定 Service 包含哪些 Characteristic，哪行是声明、哪行是数据、哪行是开关。

“表格数据载体与搬运引擎”：提供四个底层要素（Handle, UUID, Value, Permissions），负责按行读写。

核心管辖范围

管业务层（应用语义）：定义如“心率服务（0x180D）”、“心率特征（0x2A37）”。

管传输层（空口发包）：定义空中原始 PDU 二进制报文。只认 Handle 行号，搬运裸字节。

空中是否有独立报文？

没有。抓包工具里抓不到所谓的“GATT 协议包”，GATT 是纯业务规范与抽象。

全部都是。空中跑的 100% 是 ATT 协议数据单元（如 Read Request, Handle Value Notification）。

二、 抓包实证：GATT 的业务意图，如何翻译成 ATT 的空口动作？

GATT 业务意图（手机 App 视角）

ATT 空口实际发包（抓包看到的 PDU）

表格上的物理动作

 

1. 发现设备上的心率服务

Read By Group Type Request

(范围 0x0001~0xFFFF, 找 0x2800)

在整张表中按列筛选：找出所有 UUID 为 0x2800 的行，圈定心率服务位于第 1 到 6 行。

2. 读取传感器佩戴位置

Read Request (Handle = 0x0006)

返回 Read Response (Value = 0x01)

直接定位第 6 行，抓取 Value 单元格里的 1 个字节（0x01）发给手机。

3. 开启心率测量实时订阅

Write Request (Handle = 0x0004, Value = 0x0001)

返回 Write Response

找到第 4 行（CCCD 开关行），将单元格内容改写为 0x0001。

4. 手环产生新心率，推送到手机

Handle Value Notification

(Handle = 0x0003, Value = 0x00 0x4B)

手环传感器更新第 3 行，ATT 搬运工直接抓取第 3 行的内容单向丢给手机，空中无 ACK。

三、 深度辨析：GATT Properties 与 ATT Permissions 的区别

对比维度

GATT Characteristic Properties（特征属性）

ATT Attribute Permissions（属性权限）

 

所属层级

GATT 层（应用业务规范）

ATT 层与安全管理层（SMP）（协议传输与安全策略）

存放位置

公开存放在特征声明行（UUID 0x2803）的 Value 字段第 1 字节。

只保存在设备本地固件/协议栈内存中，不在大表 Value 里存储。

是否向空口发送？

会发送。服务发现时，作为声明元数据明文传输给手机。

绝不向空口发送。客户端在空中抓包里根本看不到权限定义。

定义的核心内容

业务功能支持：Read, Write, Notify, Indicate。

安全访问门槛：读写条件、是否需加密链路、认证绑定或授权。

违规行为与执行者

软性提示。供手机 App 决定提供何种功能界面，无法硬性拦截违规发包。

硬性拦截。设备端 ATT 协议栈在收到报文的第一时间校验，不符直接回绝（如 0x05）。

四、 附录：BLE ATT 全量指令 / PDU 速查表

在空口抓包中，所有的读写、检索与推送全部由以下标准的 ATT PDU 承载：

Opcode

ATT PDU 指令名称

发起方向

机制类型

指令功能与映射到大表的操作

 

0x01

ATT_ERROR_RSP

Server → Client

Response

通用错误应答。当请求的 Handle 不存在、权限不足（未加密/未认证）时返回。

0x02

ATT_EXCHANGE_MTU_REQ

Client → Server

Request

客户端请求协商双方的 ATT 最大传输单元 (MTU)。

0x03

ATT_EXCHANGE_MTU_RSP

Server → Client

Response

服务端回复自身支持的 MTU，双方取较小值作为后续单包上限。

0x04

ATT_FIND_INFO_REQ

Client → Server

Request

在指定 Handle 区间内查找所有行对应的 Handle 和 UUID（常用于查找描述符 CCCD 0x2902）。

0x05

ATT_FIND_INFO_RSP

Server → Client

Response

返回指定区间内的 Handle 与 UUID 列表。

0x06

ATT_FIND_BY_TYPE_VALUE_REQ

Client → Server

Request

按类型 UUID 及特定 Value 内容搜索匹配的 Handle 范围（常用于按服务 UUID 检索）。

0x07

ATT_FIND_BY_TYPE_VALUE_RSP

Server → Client

Response

返回匹配行的起始 Handle 与结束 Handle 列表。

0x08

ATT_READ_BY_TYPE_REQ

Client → Server

Request

在给定区间搜索指定 UUID 的行并返回其 Value（常用于读取 0x2803 特征声明行）。

0x09

ATT_READ_BY_TYPE_RSP

Server → Client

Response

返回搜索到的 Handle 及其 Value 列表（包含特征属性、值 Handle、特征 UUID）。

0x0A

ATT_READ_REQ

Client → Server

Request

直接指定 Handle，请求读取该行的 Value 内容。

0x0B

ATT_READ_RSP

Server → Client

Response

返回该 Handle 对应的 Value 单元格字节内容。

0x0C

ATT_READ_BLOB_REQ

Client → Server

Request

长数据分片读取：指定 Handle 与偏移量 (Offset)，拉取超长 Value 的后续分块。

0x0D

ATT_READ_BLOB_RSP

Server → Client

Response

返回从指定偏移量开始的 Value 切片字节。

0x0E

ATT_READ_MULTIPLE_REQ

Client → Server

Request

一次性指定多个 Handle 列表，请求打包读取多个定长 Attribute 的 Value。

0x0F

ATT_READ_MULTIPLE_RSP

Server → Client

Response

按请求顺序串联返回多个 Attribute 的 Value 组合流。

0x10

ATT_READ_BY_GROUP_TYPE_REQ

Client → Server

Request

按分组类型 UUID（如 0x2800 主服务）扫描表，获取每个服务区块的起始与结束 Handle。

0x11

ATT_READ_BY_GROUP_TYPE_RSP

Server → Client

Response

返回服务分组列表（各主服务的 Start Handle, End Handle, Service UUID）。

0x12

ATT_WRITE_REQ

Client → Server

Request

向指定 Handle 写入 Value（带应用层确认），需等待服务端回复才能发下一包。

0x13

ATT_WRITE_RSP

Server → Client

Response

服务端确认写入完成的响应报文（无数据 Payload）。

0x52

ATT_WRITE_CMD

Client → Server

Command

无应答写入（Write Without Response）。客户端无需等回包，常用于高频推流或 OTA。

0xD2

ATT_SIGNED_WRITE_CMD

Client → Server

Command

带签名写入。尾部附加 12 字节基于 CSRK 的认证码，用于未加密链路的可靠无应答写。

0x16

ATT_PREPARE_WRITE_REQ

Client → Server

Request

长数据切片写入预存：携带 Handle、Offset 和切片 Value 暂存至服务端缓冲区。

0x17

ATT_PREPARE_WRITE_RSP

Server → Client

Response

服务端回显校验收到的切片内容，确认缓冲成功。

0x18

ATT_EXECUTE_WRITE_REQ

Client → Server

Request

提交执行长数据写入：传 0x01 执行全量写入，传 0x00 则放弃并清空写入缓冲队列。

0x19

ATT_EXECUTE_WRITE_RSP

Server → Client

Response

服务端确认队列数据已原子提交写入完成。

0x1B

ATT_HANDLE_VALUE_NTF

Server → Client

Notification

无应答数据推送（Notification）。服务端主动将指定 Handle 的 Value 推给客户端，无 ACK。

0x1D

ATT_HANDLE_VALUE_IND

Server → Client

Indication

带确认数据指示（Indication）。服务端主动推送数据，要求客户端回复确认。

0x1E

ATT_HANDLE_VALUE_CFM

Client → Server

Confirmation

客户端回复 Indication 的确认报文，服务端收到后方可发下一个指示。
