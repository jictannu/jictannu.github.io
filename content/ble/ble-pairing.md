你配对自己的蓝牙耳机时，脑子里从没出现过"加密"两个字。别人能不能窃听你在听什么歌？你不在乎。你在乎的只有一件事：这台耳机和这台手机，一一对应——它只认我，不认别人；我也只连它，不连到隔壁的耳机。

客户也一样。问出"为什么蓝牙耳机开盖即连、我们的设备非要弹配对框"的时候，他要的不是"更安全的加密"，是"更无感的对应"。

这句话里，藏着蓝牙安全的全部真相。这篇文章不讲 SMP 规范的逐条搬运，也不教你在 SDK 里把参数试到能跑。它要说清三件事：

1. 你以为配对是为了加密，其实你从头到尾要的是<strong>对应</strong>；
2. 加密和对应，是同一把密钥的两面——你没法只要一个；
3. 还有第三样东西叫<strong>身份</strong>，它才是真正的难点，而且它没有数学解。

## 一、拔掉那根线，你丢了什么

先回到更根本的问题：蓝牙和有线，到底差在哪。

一根线给了你两样东西，无线电全都没有：

- <strong>机密性</strong>。数据在空气里广播，旁边任何人都收得到；有线是你俩之间的一根铜线，天然只有你俩能读。
- <strong>身份</strong>。你插上那根线，就"看见"对面是谁；无线里你什么都看不见，只有一个地址和一个可以伪造的名字。

蓝牙安全做的事，就是用密码学把这两样东西在无线里重建出来。记住这个"重建"，后面所有的困惑都从这里来。

## 二、加密和对应，是同一把钥匙的两面

重建机密性，靠的是 ECDH：双方交换公钥、各自算出共享秘密，旁观者录下全部空口报文也反推不出私钥。这个共享秘密，就是配对最终产出的那把密钥（LE Secure Connections 下叫 LTK）。

现在看这把密钥干了什么——它同时干了两件事：

1. <strong>机密性</strong>：拿这把密钥把链路加密，你的歌就变成别人读不懂的密文。这是你不关心的那件。
2. <strong>对应</strong>：这把密钥只有你俩有。别人想连你的耳机？它没有这把钥匙，加密握手根本做不成，链路要么失败、要么停在未加密状态，受保护的服务一律拒之门外。于是这把钥匙把你俩锁成了一对。这是你从头到尾真正在乎的那件。

看出来了吗：<strong>机密性和对应，是同一个密钥的两面，一起建立、一起存储。</strong> 你对工程师说"我不要加密、我只要对应"，就像说"我要这把锁、但不要这把钥匙"——做不到。要对应，就必然要那把密钥；要那把密钥，就必然带出加密。你以为自己在二选一，其实它俩是一件事。

这也是为什么开盖即连的耳机，背后其实也有一把密钥在起作用：它开盖回连时，就是用上次配对存下的 LTK 直接加密上电，邻居的手机没这把钥匙，连不进去。你没看见加密，不是因为没有，是因为协议栈在后台悄悄干完了。

## 三、你真正缺的是"身份"，而它没有数学解

如果故事到这就结束，蓝牙安全就太简单了。问题在于：<strong>"对应"不等于"身份"。</strong>

"对应"保证的是：连上我的设备，持有我们上次建立的那把密钥。它防的是"陌生人"——邻居的手机、路过的随便一台设备。

"身份"要保证的是：对面确实是它声称的那台，不是一个在我俩第一次握手时蹲在中间的冒充者。它防的是"骗子"——主动的中间人攻击（MITM）。

这里有一个冷冰冰的事实：<strong>没有任何算法能凭空证明"对面是谁"。</strong> ECDH 能证明"我俩共享一个秘密"，证明不了"对面的确实是你要找的那台设备"。机密性有数学解，身份没有——身份不能从无线电里长出来，只能从一个<strong>第三方无法同时伪造的事实</strong>里借。

这个世界上，能当这个事实的，只有三个来源：

- <strong>人</strong>：点一下确认、比对六码、输入配对码，都是把"对面是谁"这个无解问题交给人来拍板。
- <strong>物理通道</strong>：NFC 碰一下、扫个二维码，用一条可信的旁路来建立身份。
- <strong>无</strong>：Just Works，干脆放弃身份确认，只留加密和对应。

你现在明白你的耳机处在哪一档了：默认的 Just Works 配对，给了你机密性和对应（所以日常里邻居手机连不上你、你的"一一对应"成立），但<strong>没有给你身份</strong>。有人在你第一次配对时蹲在中间冒充，你俩都会以为连上了对方，而中间人能在两端各完成一次合法密钥交换，解密、查看、篡改、再转发。大多数人一辈子遇不到，所以无感；车、医疗、支付要防的，正是这个第三样。

顺带说清一个前提：Just Works 挡不挡被动窃听，要看密钥怎么建立的。LE Secure Connections（BLE 4.2+）下，共享秘密来自 ECDH，旁观者录下全部公钥报文也算不出密钥，所以能抗被动窃听，只是不抗主动冒充。而 Legacy 配对里的 Just Works，TK 就是 0，旁观者可以直接算出本次的短期密钥 STK 来解密——连被动窃听都挡不住，更谈不上身份。所以"加密已打开"不能当验收结论，得先问是哪种密钥建立方式。

## 四、那些让你困惑的场景，全是这把钥匙的落点

有了"一把密钥、三重身份"这个框架，你之前所有困惑的场景，都能在它上面找到位置，而不是一条条并列的知识点。

<strong>为什么要点这一下？</strong> 因为你刚把线拔了。有线时代身份由铜线保证；无线里任何人能冒充你的耳机，系统必须问你："你要连的是不是这个？" 你点的那一下，就是在给第三样（身份）付账——前两样（机密性、对应）协议栈早在后台给完了，所以你只记得那一下。弹窗不是 UI 啰嗦，是身份问题在第一次握手时必然要人出面的形态。

<strong>那个六位数怎么来？</strong> 它不是固化在 Flash 里的设备密码，而是本次配对中"第三方无法同时伪造的共享事实"：一侧显示、另一侧输入（Passkey Entry），或两边都显示、由人比对是否相同（Numeric Comparison）。数字本身不重要，重要的是中间人没法同时骗过两端。补充一句：Numeric Comparison 只在 LE Secure Connections 下才有，Legacy 配对没有这个模型。

配对码折腾人，最常见的原因是：固件初始化时照着 SDK 模板把 IO 能力写成了 DisplayOnly，实际硬件连屏幕都没有——协议栈自然让手机索要一个设备端根本显示不出来的数字。这不是手机乱弹框，是硬件能力声明和产品事实不一致。

<strong>又要无感又要安全？</strong> 答案是严格区分 Pairing 和 Bonding。第一次建立信任时，Pairing 协商能力、建立密钥；用户通过 Passkey、Numeric Comparison 或 OOB 参与一次身份确认。随后若双方选择 Bonding，就把长期密钥和身份资料（LTK、IRK 等）存进非易失存储。日常回连时，双方用保存的 LTK 直接启动加密，不再输码、不再比对。所以无感不是降低了安全，而是<strong>复用了第一次的安全</strong>。若启用了地址隐私，持有 IRK 的一方还能解析对端轮换的 RPA 地址——但 IRK 是身份解析/隐私的一部分，并非每次绑定都必然需要。

对于物理上就是 NoInputNoOutput 的设备，别强行伪造 Passkey。链路层只能 Just Works + Bonding 建立基础加密；若业务真要识别真设备，就把安全能力上移到应用层——设备公钥或证书二维码可信引导，再做 challenge-response。二维码、私钥保护、设备实体绑定、服务端信任必须共同成立，单独"贴二维码"不是完整方案。

## 五、参数是标签，不是开关

到这里再回头看芯片 SDK 那一堆 Mode、Level，才知道它们是在描述"这把钥匙重建到了哪一档"。

Security Mode 1 管的是链路加密：

- Level 1：无安全；
- Level 2：未认证加密（有密钥、有加密，但没验过身份）；
- Level 3：已认证加密（完成了身份确认）；
- Level 4：已认证的 LE Secure Connections（额外要求 SC 方式建立密钥）。

注意 Level 3 的关键不在"用了 Passkey"，而在"完成了认证"；Level 4 在认证之上再要求 SC。

Security Mode 2 走的是另一条路：数据签名。它不把整条链路变密文，而是用 CSRK 给 Signed Write Command 提供来源和完整性验证。它回答的是"这次写入确实来自绑定过的那台设备"，不提供机密性——正好对应"身份有、机密性无"这一档。它不是"更高级的通用配对模式"，别拿它当 Mode 1 的升级版。

所以面对需求，别先问"SDK 里该打开哪个 Mode"。先问三件事：要保护哪项数据或命令？只防抓包，还是要防主动仿冒？硬件到底提供哪些真实可靠的交互能力？——也就是：要机密性、要对应、还是要身份？要哪一档，参数自然有唯一的理由，不用排列组合硬试。

## 六、收束：一根线的三重重建

把视角拉回协议栈，整件事就清楚了：

- GATT / ATT 决定哪些特征值需要何种保护，并在安全不足时拒绝访问（0x05 Insufficient Authentication、0x0F Insufficient Encryption）；
- L2CAP 提供 SMP 使用的固定信道 CID 0x0006；
- SMP 协商 IO 能力、关联模型、密钥与绑定资料；
- Link Layer 用协商或已保存的密钥启动加密。

蓝牙安全，说到底就是一句话：把一根有线电缆天然有的机密性和身份，用密码学在无线里重建出来。机密性靠 ECDH，对应是同一把密钥的副产品，身份靠人、物理通道或放弃三选一。你配耳机时没想过加密，但你要的"一一对应"，恰恰是这把密钥的另一面；而你从没在意过的"身份"，才是真正值得花时间搞清楚的那一样。
